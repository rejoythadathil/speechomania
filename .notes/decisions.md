# Decision log

The codebase has zero comments, so the reasons behind choices live here. Newest last. Add a row when a decision changes; don't edit old rows.

| Date | Decision | Why |
|---|---|---|
| 2026-10-25 | JavaScript, not TypeScript | Team choice. |
| 2026-10-25 | Zero comments in the codebase, enforced by pre-commit | Team choice. Reasons go in these notes instead. |
| 2026-10-25 | Bun runtime + Hono framework for API and worker | Fast and lightweight; Hono also runs on Node if Bun ever blocks us. Firebase admin, BullMQ and Playwright must be checked on Bun in phase 0. |
| 2026-10-25 | One organisation, role-based access only; no multi-tenancy | Speechomania is a single organisation. Roles: admin, mentor, parent; children are profiles owned by a parent. |
| 2026-10-25 | Admins can write remarks too | `remarks.author_id` can be a mentor or an admin. |
| 2026-10-25 | 7 tables: users, children, lessons, attempts, remarks, change_requests, audit_logs (8 since 2026-11-01) | Keep the schema minimal; use columns, the queue, S3 and the audit log before adding tables. |
| 2026-10-25 | `metadata jsonb NOT NULL DEFAULT '{}'` on every table | Room for extra values and future data transfer without a migration. |
| 2026-10-25 | Single prod VM; recovery built in phase 0 (PITR, RPO 5 min, RTO 1 h) | Accept one VM only with tested recovery. |
| 2026-10-25 | Host nginx as reverse proxy and load balancer over `api-1` and `api-2` | Same pattern as xam; rolling deploys with no downtime and use of more than one CPU core. |
| 2026-10-25 | Two environments: local (development) and prod | No second VM. Local uses RustFS and the Firebase Auth Emulator, so it never touches prod resources. |
| 2026-10-25 | Tailwind v4 + CSS modules, React 19 | Needed for BoardUI. |
| 2026-10-25 | BoardUI free components only, no Pro | Missing components are built in `components/shared/`. |
| 2026-10-25 | Mochi Icons for child mode only | Child mode is interactive; work views stay professional. An ESLint rule keeps the two apart. |
| 2026-10-25 | RustFS replaces MinIO for local S3 | The `minio/minio` image can no longer be pulled. RustFS is S3-compatible and Apache-2.0. |
| 2026-10-25 | Own 25-line migration runner instead of dbmate | dbmate needs `-- migrate:up` comment markers, which the zero-comments rule forbids. |
| 2026-10-25 | `children.assigned_lessons` is `jsonb`, not `citext[]` | Bun's Postgres client sends array parameters incorrectly; JSON round-trips cleanly. |
| 2026-10-25 | BoardUI components converted from TSX to JSX | The codebase is JavaScript only. Conversion strips types and comments; re-run it after every `boardui add`. |
| 2026-10-25 | BoardUI application blocks removed (sidebar, stat cards, auth card, data table) | They are not in BoardUI's published free list. Our own sidebar, stat card and modal replace them. |
| 2026-10-25 | One `work-layout` for admin, mentor and parent | The three layouts would be identical apart from the menu, which comes from `navigation.js`. |
| 2026-10-25 | Multi-role pages live in `views/shared/`, admin-only pages in `views/admin/` | Children, child detail, lessons and change requests are one page each whose actions change by role. |
| 2026-10-25 | Unauthorised records return 404, not 403 | A mentor or parent cannot tell whether another family's child exists. Wrong-role actions still return 403. |
| 2026-10-25 | Invite links are shown to the admin to send | No email provider is chosen yet. Firebase creates the link; the admin copies it. Replace with email when a provider is chosen. |
| 2026-10-25 | pgBackRest runs inside the Postgres container | Postgres calls `archive_command` itself, so the tool must be in the same container. |
| 2026-10-25 | API port 4100 and local services on 7101–7106 | Ports 4000 and 6101–6102 are already used by the xam stack on the dev machines. |
| 2026-10-25 | Work views use a flat, dense style (hairlines, no shadows, small radius, joined stat strip) | The first version had too much space between cards. The team chose rightfit.so as the reference. Tokens live in `app.speechomania/src/styles/brand.css`. |
| 2026-10-25 | Dashboard charts are our own SVG components (`components/shared/charts/`), not BoardUI Pro or a chart library | BoardUI's dashboard templates are Pro. The charts keep the flat style, use one colour per chart, and each has keyboard tooltips and a table view. Mentors see only their own data. |
| 2026-10-25 | Dashboard answers "which child needs attention" instead of showing activity | Percent changes on small numbers and the audit-log heatmap didn't lead to any action. Follow-up rules (no mentor, no remark in 14+ days, no lessons) are computed in SQL so the sidebar badges and the dashboard agree. |
| 2026-10-25 | No mock data anywhere; demo data only from `api.speechomania/seeds/dev.js` | Recorded in the root `CLAUDE.md` so every session follows it. |
| 2026-10-25 | Staff avatars are DiceBear Gaze, generated locally, seed stored in `users.metadata.avatar` | The team picked Gaze. Rendering from the npm package avoids sending user ids to a third party and needs no CSP change (`data:` images are already allowed). No new column: it lives in `metadata`. |
| 2026-10-25 | One pagination contract for every list: `page`/`page_size` in, `{ items, page, page_size, total, total_pages }` out, count in a separate query | The old `count(*) OVER ()` returned `total: 0` when a page was past the end, and four lists (remarks per child, unread remarks, lesson versions, dashboard follow-up) were unbounded. Screens choose their own page size (max 100). |
| 2026-10-25 | Tighter domain scoping | Parents only see lessons assigned to their children; editing or deleting a remark rechecks that the child is still in the user's scope (so a mentor moved off a child loses access); mentors no longer receive parent emails. Covered by `test/scoping.test.js`. |
| 2026-10-25 | Global search in the header (`GET /v1/search`): pages, children, lessons, people (admins) | Built on the same scoped list services as the screens, so scoping can't drift. Keyboard-first (⌘K, arrows, Enter, Esc), with "See all" links into each filtered list. |
| 2026-10-25 | Every list shows a footer with "X–Y of Z", rows per page and a pager; page and size live in the URL | Lists that fit on one page used to show no count or pager, which looked unpaginated; refresh and Back lost the page. The rows selector is a native `<select>`: the BoardUI popover closed itself when it opened near the bottom of the page. |
| 2026-10-25 | Parent and mentor pickers search the server instead of loading 100 people | The old pickers would silently miss people once Speechomania has more than 100 parents. |
| 2026-10-26 | Prisma Migrate (7.10.1) for schema and migrations; queries stay on Bun.sql (replaced 2026-10-31) | The team wanted a typed schema file and standard migration tooling. Prisma Client is not used: the scoped Bun.sql services already work and are tested. Prisma's generated comments are stripped by `migrate:new`, and the pre-commit hook blocks comments in `.sql` and `.prisma`. The config is `prisma.config.mjs` (JS only). Stayed on 7.10.1 because `latest` on npm is an 8.0 release candidate. |
| 2026-10-26 | One repository instead of three | The team chose github.com/rejoythadathil/speechomania for everything. The three local repos had no commits, so nothing was lost. Hooks and CI moved to the root; workflows are filtered by folder. Release deploy jobs stay off until `DEPLOY_ENABLED` is set, because the prod VM and its secrets don't exist yet. |
| 2026-10-26 | The product is Speechomania, owned by Autism Synergies, not DCCD Global | The founder clarified that this is not DCCD Global and will be published on the Speechomania website under the Autism Synergies company. Visible text, page title, docs and every internal identifier (folders, containers, database, roles, image and project names) now say Speechomania; nothing was deployed, so no data or running system was affected. Still open: Speechomania's own logo and colours (the old mark was modelled on DCCD's logo and has been replaced by a placeholder), the consent wording (who is the data controller), and the production domain (`speechomania.example` is a placeholder). Older entries above keep the name that was current when they were written. |
| 2026-10-26 | The repository is github.com/rejoythadathil/speechomania | The first repo (rejoyt/autismsynergies) was deleted and replaced by this one. The remote and every doc reference were updated. |
| 2026-10-29 | Child mode is built: `layout/learning-layout`, `views/child` (shelf, lesson player) and `components/child`; the parent opens it with "Start learning" on the child's page | Modelled on the MVP's "Who can't?" book and the founder's references (Khan Academy Kids, HOMER, Duolingo ABC): every lesson happens inside a calm scene, characters stand on the ground, controls float as large rounded buttons. Autism research on picture backgrounds (busy backgrounds pull gaze away from faces) is why the scene is muted and sparse and the characters are the only outlined, saturated shapes. |
| 2026-10-29 | Child mode talks to its own parent-only API, `/v1/learning` (child, shelf, playable lesson, attempts, exit) | The child has no login; the parent's session plays. Ownership is in SQL (`children.parent_id`), other parents get 404 and staff get 403, covered by `test/learning.test.js`. The shelf keeps the pagination contract. |
| 2026-10-29 | A second lesson player, `pick` ("tap the one who can't"), lives in `lessons.content` (`player`, `contrast`, `lines`, and per step `choices`, `answer`, `actor`, `act`, `praise`, `teach`) | No new table or migration: content is already versioned jsonb. Joi checks that the answer and the acting character are one of the two pictures. Characters and actions are fixed lists in the lessons `constants/index.js`, mirrored by the drawings in `components/child/characters.js`. |
| 2026-10-29 | Characters are drawn in-house as one flat SVG set (child proportions, dot eyes, one outline), and the "can" character acts the verb out after the answer | The founder found the Open Peeps faces confusing, and the MVP mixed clip-art styles with a photo. One consistent set is easier to read and has no licence questions. The act-out only appears after the child answers, so Show me pages still test fairly. The SVG markup is static and rendered from a whitelist of ids. |
| 2026-10-29 | Lesson audio comes from ElevenLabs through `common-service/voice`, run by `bun run audio <slug>` until the worker exists | The script writes audio into a draft version (published rows never change); an admin then publishes it. Files are keyed by a hash of voice, model, settings and text, with the word timings in a JSON file beside the MP3, so a line is never paid for twice and read-along follows the real voice. Same voice (Lily) and calm settings as the MVP. The worker will call the same function. |
| 2026-10-29 | Children get audio through short-lived signed S3 URLs; the static site CSP gains `media-src 'self' https:` | Matches the plan for private media behind signed URLs. Locally the bucket is created with one signed `CreateBucket` call because Bun's S3 client cannot create buckets; prod buckets come from the first-setup runbook. |
| 2026-10-29 | Stars are computed by the API from first-try answers on Show me pages; a sticker needs 90% | The client cannot award itself stars. 90% is the MVP's mastery default. Rewards only add. |
| 2026-10-29 | Leaving child mode needs the parent's 4-digit PIN, or a 2-second press and hold when no PIN is set | The PIN is set by the parent only, hashed with `Bun.password` into `children.pin_hash`, and never returned (`has_pin` only). Press-and-hold keeps a toddler from leaving by accident without forcing every family to set a PIN. |
| 2026-10-29 | Mochi Icons has no next, back or pause icons, so those three are made with Mochi's own `createIcon` in `components/child/child-icons.jsx` | One file holds every child icon, so one icon always means one thing. |
| 2026-10-29 | The child shelf uses large "Back" and "More books" buttons instead of `ListFooter` | `ListFooter` is a BoardUI work-view component and child mode never uses BoardUI. The server contract (`page`, `page_size`, totals) is unchanged. |
| 2026-10-29 | Sensory settings drive child mode: motion `normal` = full, `reduced` = gentle (no idle loops or drifting clouds), the device's reduced-motion setting = off; sound `quiet` = half volume, `off` = captions only; colour `low` = softer colours | These are the parent's settings on the child profile; the child cannot change them. Captions and the word highlight always run, with or without sound. |
| 2026-10-29 | Every API module keeps one concern per file: route, controller, service, validation, constant, exception, utils, test and docs (`<name>.<kind>.js`, `<name>.docs.md`), in both `common-service/` and `src/routes/v1/` | The team asked for constants, controllers, docs, exceptions, routes, services, tests and utils to be separate. Errors are named factories, so the same message is not retyped across services; pure helpers can be unit-tested without a database; tests and docs sit next to the code they describe. Root `utils.js` became `common-service/http/`. Files are created only when they have content (no empty placeholders). |
| 2026-10-29 | Each kind of module file lives in its own sub-folder (`route/`, `controller/`, `service/`, `validation/`, `constants/`, `exception/`, `utils/`, `tests/`, `docs/`) | The team organised `common-service/voice/` this way and asked for every module to match. Folder names follow that example exactly. |
| 2026-10-29 | Module files are `index.js` inside their kind folder (`tests/index.test.js`, `docs/index.md`) | Requested by the team; the folder already names the kind and module. Tests keep `.test.js` because `bun test` only discovers that suffix. |
| 2026-10-31 | All art, icons, scenes and effects are downloaded assets or libraries, never hand-drawn SVG, CSS or canvas; sources and licences go in `.notes/assets.md` | The team asked for this strictly: hand-drawn art looks amateur and costs time. Licensed packs and the therapists' own lesson pictures look consistent and are traceable. |
| 2026-10-31 | Each lesson is its own game (`player`), chosen from the therapists' material: shark, balloons, bubbles, squish, compare, hide, train, yesno, why, plus pick and story | Children with autism engage longer with a clear, repeatable game than with a book; one mechanic per lesson keeps each one predictable while the set stays varied. New games are a new player value, a schema in the lessons validation and one file in `views/child/games/`. |
| 2026-10-31 | Games play `rounds` steps chosen at random from the lesson, wrong options come from the lesson's own steps | Short sessions (6 to 8 rounds) suit attention spans; drawing distractors from the same lesson keeps all content in the database. |
| 2026-10-31 | Lesson pictures live in S3 under `lessons/<slug>/`, uploaded by the seed from `api.speechomania/seeds/media/`, and are signed per request | Same path as audio: no lesson files ship in the app, and prod content is managed without a deploy. |
| 2026-10-31 | Hand-drawn characters, scene and actor removed from child mode | Replaced by OpenMoji art under the "download, never hand-draw" rule. |
| 2026-10-31 | Child mode uses vector illustrations only (OpenMoji, named in lesson `art`), no photos; the photo seed folder was removed | The team wants one clean, consistent picture style for children and no external photos. Naming art keeps lessons as data and makes new lessons possible without uploads. |
| 2026-10-31 | Parents sign in straight to `/learn` (one child opens directly, several get a picker) | Fewest taps from sign-in to learning; the grown-up screens stay one tap away. |
| 2026-10-31 | The home greeting is not spoken | Names change per child, so only the browser voice could say it; mixing it with the ElevenLabs voice was jarring. |
| 2026-10-31 | Sign-in is a minimal white brand page (logo, "Welcome back", form, footer) | The team wants a professional, simple sign-in with none of the playful child-mode styling. |
| 2026-10-31 | Each game has its own theme and scenery defined in one file (`scenes.js`), and the lesson start page shows the game world beside its title and how-to-play tips | Variety between games while buttons, voice, stars and trophy stay the same everywhere; one place to change a game's look. |
| 2026-10-31 | The games home is a thumbnail grid (game world picture, tag, stars) | Chosen by the team over a path, islands, a carousel and a map: each game is recognisable from its picture and the grid is easy to scan. |
| 2026-10-31 | Child mode is flat (hairline borders, no shadows) and the home shows badges collected | The team wants a calmer, more organised home; a badge per game finished with nine tenths of its stars gives a clear goal without new tables (computed from attempts). |
| 2026-10-31 | The child's home fuses the work-view look (summary, stats, badges) with a creative games area | The team wants the details to read like the admin screens while the games stay playful. Reusing `components/shared` keeps one style for summaries without bringing BoardUI into child mode. |
| 2026-10-31 | The child's home is one framed unit: stats, games and badges share one frame, one type and one border style | The team rejected a details band stacked over a separate play band. One frame with hairline dividers reads as a single page; the creativity lives in the game thumbnails and the sky around the frame. |
| 2026-10-31 | All database access moved to Prisma Client; no raw SQL in app code | The team wants one readable query style and no hand-written SQL in services. Queries use the model APIs through `@prisma/adapter-pg`; ownership scopes are `where` clauses. Game scoring (`maxStars`, best stars per lesson) and dashboard series moved out of SQL into tested `utils/` functions. Row locks (`FOR UPDATE`) were replaced by `Serializable` transactions that return 409 on a clash. Raw SQL stays only in migrations and the test database setup (creating the test database and grants). Replaces the 2026-10-26 "queries stay on Bun.sql" decision. |
| 2026-10-31 | The lesson page shows the lesson the way the child plays it, for every role that can open it | Staff and parents only saw step text before. Now they see the game, each round's pictures and right answer, the spoken lines and voice status, built from the same downloaded art and scenes as child mode. Parents can open lessons assigned to their children (the API already scoped this). |
| 2026-11-01 | Assessments get their own table (the eighth) | The team chose a dedicated `assessments` table over storing them as lessons. Assignments stay on the child (`assigned_assessments`) and results reuse `attempts` (`assessment_id`, with a CHECK that an attempt belongs to a lesson or an assessment, never both). Questions are copied in when saved so later lesson edits never change an assessment or its results. |
| 2026-11-01 | Every assessment option is set by the admin per assessment, and the API enforces data collection | The team wants scoring and what is recorded to be configurable. Settings cover points, tries, points for a later try, pass mark, shuffle, hints, retakes, which data points are kept (answer tapped, time, wrong tries) and who sees the score. The API strips switched-off data points before saving, so a setting cannot be bypassed by the app. Assessment attempts never earn stars or badges. |
| 2026-11-01 | No proctoring | The team wants assessments to be simple records played like lessons: no timers, locks or supervision. |
| 2026-11-01 | Prettier formats both apps; lint fails on unformatted code | Long one-line calls and objects were hard to read. Prettier (no semicolons, single quotes, 100 columns) breaks them onto indented lines. BoardUI's own components are left as shipped. |
| 2026-11-01 | `migrate:new` uses `prisma migrate diff` against the local database | `prisma migrate dev` needs a shadow database, which cannot replay the migration that revokes `_prisma_migrations` from the app role. Diffing against the migrated local database gives the same SQL without the shadow database. |
| 2026-11-01 | Lessons and assessments share one play session in child mode, with a staff preview | `PlaySession` runs lesson rounds, assessment questions (each in its own game) and the staff preview. The preview uses the same art, voice and effects inside `PreviewStage` and sends nothing to the API. |
| 2026-11-02 | Child-mode controls use OpenMoji instead of Mochi Icons; Mochi is removed | The team found the icons mismatched: Mochi's coloured lock and speaker sat next to hand-drawn line arrows and pause, and those hand-drawn icons broke the download-only rule. OpenMoji has every control (lock, sound, pause, arrows, check), in the same style as all lesson pictures. Replaces the 2026-10-25 and 2026-10-29 Mochi decisions. |
| 2026-11-02 | Decoration is still and belongs to each game's world | The team found the floating emoji random and meaningless. Scenes keep one to three pieces that fit the world, nothing bobs or drifts, the home and picker lose their clouds and rainbow, and how-to-play tips show the action. The grey game controller stat icon became a check mark to match the other colours. |
| 2026-11-04 | Prod starts on one $18 Droplet with one hostname | The budget is $20 a month. One host for the app and API (`/v1` on the same origin) needs one certificate and one DNS record on Vercel, and avoids CORS. The subdomain layout stays available with `SINGLE_HOST=0`. |
| 2026-11-04 | Every merge to `main` deploys, and the VM pulls instead of CI pushing | The team wants no production environment or approval step. CI only pushes images to GHCR; a cron job on the VM deploys new `:prod` images. GitHub holds no SSH key, so a leaked CI token cannot reach the server. People sign in as their own admin user; root SSH is off. |
| 2026-11-04 | `app.speechomania/.env.production` is allowlisted in gitleaks | It holds the Firebase web config, which is public by design and ships inside the app bundle. Access is controlled by Firebase authorized domains and the API, not by hiding the key. The service account key stays only on the server. |
| 2026-11-04 | Prod media lives in RustFS on the Droplet instead of R2 or Spaces | R2 needs a payment method on file and Spaces adds $5 a month past the $20 budget. RustFS is the same S3 server used locally and costs nothing; the trade-off is no copy off the box until backups are built. |
| 2026-11-04 | Prod gets a tagged demo seed until real families join | The team wants every screen visible on prod before launch. The normal seed would create logins with a password that is public in the repo, so `--demo` creates people without sign-in, uses a real admin as owner and tags every row `metadata.demo`. `seeds/demo-remove.js` removes the demo and keeps the lessons. |
| 2026-11-04 | Generated scenes are used only as whole game pictures (thumbnails and the lesson start page) | They are a richer style than OpenMoji. Shown as a framed picture of the game's world they don't sit beside the icons, so child mode keeps one icon family. Rounds, controls, avatars and rewards stay OpenMoji. Games without a usable scene keep the OpenMoji composition. |
| 2026-11-05 | The child-mode exit button reads "Parent" instead of "Grown-ups" | The team wants the label to name who it is for. Only the visible copy changed; component names stay. |
